# Общий контракт UI ↔ логика: `rubrica --html`

**Фича**: `001-html-report`
**Статус**: Draft для согласования, до генерации кода
**Дата**: 2026-11-02
**Решения принимает человек**; этот файл — результат согласования двух команд.

## 1. Наблюдаемая CLI-поверхность

```text
rubrica <target> [--spec PATH] [--json] [--max-findings N] [--narrative]
                 [--model ID] [--timeout SECONDS] [--html PATH]
```

- `--html PATH` — необязательный экспорт. Без флага поведение полностью прежнее.
- `--html` можно комбинировать с `--json`: stdout остаётся чистым JSON прежней
  схемы, HTML пишется отдельным файлом.
- `--html` не меняет stdout: текст или JSON печатаются как раньше.
- При успешной записи в stderr печатается ровно одна строка:
  `HTML-отчёт: <абсолютный путь>`.
- `--max-findings` остаётся ограничением **только текстового stdout**.
  JSON и HTML содержат все находки. Это фиксирует уже существующее поведение
  JSON и не добавляет скрытых данных в HTML.

### Коды возврата

| Ситуация | Код |
|---|---:|
| аудит 0/1/2, HTML записан | код аудита (0/1/2) |
| аудит 0/1/2, `--narrative` не удался, HTML записан | 3 (сохраняем текущее поведение) |
| путь `--html` отклонён до аудита | 2, аудит не запускается |
| ошибка записи после аудита | 2, отчёт аудита уже напечатан |
| ошибка записи и недоступная рецензия одновременно | 2 (ошибка экспорта важнее) |

`3` не отменяет и не искажает вердикт аудита: в HTML показываются баллы,
находки и отдельный бейдж «Рецензия недоступна».

## 2. Контракт пути `--html`

Валидация выполняется в `report_html.resolve_output_path()` **после**
`validate_all()` (ошибки target/spec сохраняют приоритет), но **до**
`load_spec()` и `audit()`.

| Случай | Решение |
|---|---|
| пустая строка или только пробелы | отказ: `--html: путь не указан` |
| `~` в начале | раскрывается `expanduser()` |
| расширение не `.html`/`.htm` | отказ: нужен `.html` или `.htm` |
| путь указывает на существующий каталог | отказ: нужен файл |
| родительская папка не существует | отказ; каталоги не создаём |
| родитель — не каталог | отказ |
| целевой файл — символическая ссылка | отказ: укажите реальный путь |
| символическая ссылка в родительских папках | допустима, родитель приводится к `resolve()` |
| существующий обычный файл | перезапись разрешена, атомарно |
| путь внутри `target` | разрешён как явное намерение пользователя |
| пробелы в пути отчёта | разрешены (в отличие от `target`) |
| относительный путь | разрешается от текущего каталога; в stderr — абсолютный |

Любой отказ → `ExportRejected` → `ОТКАЗ: HTML-отчёт не записан — <причина>`
в stderr и код 2. Частичный файл не создаётся.

## 3. Контракт данных

`ReportView` — неизменяемая модель только из примитивов:

| Поле | Тип | Смысл |
|---|---|---|
| `spec_id`, `spec_title` | `str` | из `Report` |
| `target` | `str` | уже разрешённый путь аудита |
| `score`, `max_score` | `int` | из `Report`, без пересчёта |
| `passed`, `failed`, `blockers` | `int` | количества, не списки |
| `exit_code` | `int` | `Report.exit_code`, только 0/1/2 |
| `findings` | `tuple[FindingView, ...]` | **все** находки в порядке рубрики |
| `warnings` | `tuple[str, ...]` | в исходном порядке |
| `narrative` | `str \| None` | как в JSON |
| `narrative_error` | `str \| None` | как в JSON |

`FindingView`: `rule`, `kind`, `severity`, `ok`, `title`, `detail`, `weight`.

Решения:

- **Нет `generated_at`**: одинаковый вход → байт-идентичный HTML. Время,
  случайные id и `hash()` запрещены.
- **Нет `hidden_findings`**: HTML не режется `--max-findings`.
- **Нет обрезки рецензии**: HTML показывает тот же текст, что JSON; иначе
  нарушается сверка «HTML = JSON».
- **Порядок по умолчанию** — порядок рубрики; сортировка выполняется на клиенте.
- **Инварианты**: `0 <= score <= max_score`; `passed + failed == len(findings)`;
  `blockers <= failed`; `exit_code == Report.exit_code`.

## 4. Python-контракт модуля `src/rubrica/report_html.py`

Только стандартная библиотека. Модуль импортирует `Report`/`Finding` из
`.core` только для чтения; не импортирует `narrative`, `urllib`, `socket`.
`core.audit()` и `core.Report` не меняются.

```python
class ExportRejected(Exception):
    """HTML-отчёт не создан; сообщение называет путь и причину."""

def build_view(report: Report, *, narrative: str | None = None,
               narrative_error: str | None = None) -> ReportView: ...

def render_html(view: ReportView) -> str: ...          # чистая функция, без I/O

def resolve_output_path(raw: str | Path) -> Path: ...  # ранняя валидация пути

def write_atomic(path: Path, text: str) -> None: ...   # temp + os.replace

def export_html(report: Report, raw_path: str | Path, *,
                narrative: str | None = None,
                narrative_error: str | None = None) -> Path: ...
```

- `export_html` — единственная точка входа для CLI:
  `resolve_output_path` → `build_view` → `render_html` → `write_atomic`.
- `build_view` не мутирует `Report`; `render_html` не бросает `ExportRejected`.
- `write_atomic`: `mkstemp` в родительской папке, запись UTF-8, `flush`,
  `fsync`, `os.replace`; при `OSError` — удалить temp и бросить
  `ExportRejected`; старый файл не трогается.
- Права результата — `0600` (отчёт может содержать имена файлов с секретами).

## 5. Контракт HTML

Один самодостаточный файл, открывается по `file://` без сети.

- `<!DOCTYPE html>`, `<html lang="ru">`, `<meta charset="utf-8">`,
  `<meta name="viewport">`, осмысленный `<title>`.
- CSP: `default-src 'none'; style-src 'unsafe-inline'; script-src 'unsafe-inline'; img-src data:`.
- Все CSS/JS встроены. Нет `<link>`, `<script src>`, `<img src>`, `@import`,
  `url(...)`, `fetch`/XHR и внешних URL в разметке.
- Каждая динамическая строка проходит `html.escape(s, quote=True)`.
- Динамические строки не попадают в атрибуты. Разрешены только контролируемые:
  `data-severity` ∈ {blocker, major, minor}, `data-ok` ∈ {true, false},
  `data-weight` — целое, `data-search` — экранированный текст.
- Без JavaScript страница остаётся полной и читаемой; фильтры — прогрессивное
  улучшение.
- Повторный рендер одного `ReportView` даёт идентичные байты (завершающий `\n`).

### Экран

**Шапка**: `Отчёт аудита rubrica`, `spec id · spec title`, target, метрики
`Баллы: P/M`, `Пройдено`, `Провалено`, `Блокеров`, `Код аудита: 0|1|2`,
баннер вердикта:
- 0 — «Все правила пройдены»;
- 1 — «Есть провалы без блокеров»;
- 2 — «Есть блокирующие провалы»;
- плюс бейдж «Рецензия недоступна» при `narrative_error`.

**Панель действий**:
- поиск `type=search` по rule id, заголовку и деталям (casefold, trim);
- селект severity: все / blocker / major / minor;
- чекбокс «Только провалы»;
- сортировка: порядок рубрики (по умолчанию), провалы сначала,
  severity blocker → minor, rule id, вес (больше сначала); сортировка устойчивая;
- кнопка «Сбросить»;
- счётчик `Показано N из M` с `aria-live="polite" aria-atomic="true"`.

Фильтры и поиск комбинируются по AND. Изменения применяются сразу, без
перезагрузки. Все контролы имеют `<label for>`, доступны с клавиатуры, фокус
видим; статус PASS/FAIL и severity передаются текстом, не только цветом.

**Список находок**: PASS/FAIL, severity, rule id, заголовок, детали, вес.
**Предупреждения**: все, с явным «Предупреждений нет».
**Рецензия**: «не запрашивалась» / текст с сохранением переводов строк /
«Рецензия недоступна: <error>. Результат аудита не изменён».

**Пустые состояния**:
- нет совпадений — «Ничего не найдено. Измените запрос или сбросьте фильтры»,
  `Показано 0 из M`, метрики шапки не меняются;
- «только провалы» при полном успехе — «Провалов нет»;
- пустой отчёт — «Находок нет», `0/0`, без падения.

## 6. Сквозная приёмка

1. `rubrica <target> --spec <rubric> --html /tmp/report.html` на сдаче без
   провалов → файл есть, код 0, stdout как без флага, stderr содержит путь.
2. Сдача с провалом major → код 1, HTML содержит FAIL, score = JSON score.
3. Сдача с blocker → код 2, HTML содержит блокирующую находку и баннер.
4. `--json --html` → stdout парсится как JSON, поля прежние, файл есть.
5. `--narrative` + замоканный отказ → код 3, HTML содержит `narrative_error`,
   баллы не изменились.
6. Неверный путь (`/nope/report.html`, каталог, `.txt`, пустой, симлинк) →
   код 2, файл не создан, аудит не запускался для ранних отказов.
7. Ошибка записи (mock `os.replace`) → старый файл цел, temp удалён, код 2.
8. Недоверенные строки `<script>`, `"><img onerror=...>` → в HTML только текст.
9. Два запуска на одном входе → идентичные байты.
10. Без `--narrative` сеть не вызывается; `core.py` не менялся; все прежние
    74 теста зелёные; `sh scripts/check.sh` — единственная проверка.
