# Спецификация (после согласования) — слой логики HTML-отчёта

**Фича**: `specs/001-html-report/spec.md` — флаг `--html PATH` в CLI `rubrica`
**Команда**: 2 (логика/данные)
**Дата**: 2026-11-02 · **Статус**: Draft после согласования
**Основание**: `specs/001-html-report/contracts/ui-logic.md` — общий контракт UI ↔ логика (решения ведущего). При расхождении с черновиками команд приоритет у контракта.

Границы: модель представления, функции, валидация пути, алгоритм рендера и атомарной записи, детерминизм, безопасность, коды возврата. Экранные состояния, тексты и контролы — зона UI; здесь фиксируются только данные и гарантии, которые UI получает.

## 1. Обязательные решения общего контракта

- `build_view` и `export_html` **не принимают `max_findings`**; HTML содержит **все** находки. `--max-findings` остаётся лимитом только текстового stdout.
- В модели **нет** `generated_at` и **нет** `hidden_findings`; HTML байт-идентичен при одинаковом входе.
- **Нет обрезки `narrative`**: в HTML тот же текст, что в JSON-поле `narrative`.
- Расширение пути — строго `.html` или `.htm` (регистр не важен); иначе отказ.
- `resolve_output_path()` вызывается **после `validate_all()`** (ошибки target/spec приоритетнее) и **до `load_spec()`/`audit()`**.
- `--html` совместим с `--json`: stdout остаётся прежним JSON, схема не меняется.
- Код 3 сохраняется как текущее поведение (в т.ч. при вердикте аудита 2); ошибка записи даёт 2 и приоритетнее 3.
- Целевой файл-симлинк отклоняется; родительские папки не создаются; права результата — `0600`.

## 2. Пользовательские истории

### US-LOG-1 (P1) — получить модель отчёта, пригодную для любого рендера

Как вызывающий код (CLI, тест, будущий MCP), я хочу из `Report` получить одну неизменяемую view model, чтобы HTML-рендер не знал о внутренностях `audit()` и не мог исказить вердикт.

**Ценность**: баллы, счётчики и находки берутся из того же `Report`, что и текст/JSON, — расхождений быть не может. **Проверка**: `build_view()` на собранном `Report` даёт ожидаемые счётчики и порядок и не меняет сам `Report`.

1. **Given** отчёт из 3 правил (2 pass, 1 fail, без blocker) **When** вызывается `build_view(report)` **Then** `score=2`, `max_score=3`, `passed=2`, `failed=1`, `blockers=0`, `exit_code=1`, 3 находки в порядке рубрики.
2. **Given** отчёт с 5 находками, среди них 2 fail **When** строится view **Then** `len(findings)==5`, `passed+failed==5`; поля `hidden_findings` нет.
3. **Given** `report.warnings` **When** строится view **Then** предупреждения попадают в view в исходном порядке и без изменений.
4. **Given** рецензия длиной 100 000 символов **When** строится view **Then** `narrative` совпадает с исходной строкой посимвольно, без обрезки.

### US-LOG-2 (P2) — безопасно записать автономный HTML-файл

Как пользователь, указавший `--html out/audit.html`, я хочу получить один самодостаточный файл, который открывается офлайн и не превращает недоверенную папку сдачи в вектор инъекции.

**Ценность**: артефакт можно приложить к сдаче; ошибка записи не оставляет «полуфайл» и не портит существующий отчёт. **Проверка**: `export_html()` пишет файл, повторный запуск даёт байт-в-байт тот же результат, при падении записи старый файл не меняется.

1. **Given** валидный view и путь `tmp/out/report.html` с существующей папкой **When** вызывается `export_html(...)` **Then** файл существует, начинается с `<!DOCTYPE html>`, содержит `<meta charset="utf-8">`, возвращён абсолютный `Path`.
2. **Given** существующий `report.html` с содержимым `OLD` **When** запись падает **Then** файл по-прежнему содержит `OLD`, temp-файлов не осталось.
3. **Given** путь `report.txt` **When** вызывается экспорт **Then** `ExportRejected` с текстом про допустимые `.html`/`.htm`.

### US-LOG-3 (P3) — не сломать существующий аудит

Как мейнтейнер, я хочу, чтобы без `--html` stdout, JSON и коды возврата остались прежними, а `core.py` по-прежнему не знал ни о рендере, ни о сети.

**Ценность**: фича аддитивна; 74 существующих теста и контракт не меняются. **Проверка**: `main` без `--html` даёт прежний stdout и код; `report_html` не импортирует `urllib`/`socket`; `core.py` не меняется.

1. **Given** сдача без `README.md` и blocker в рубрике **When** `main` без `--html` **Then** код 2, `ОТКАЗ` в stderr, файлов не создано.
2. **Given** валидная сдача **When** `main` с `--html /nope/report.html` **Then** `validate_all` проходит, путь отклоняется до `load_spec`/`audit`, аудит не запускается, код 2.
3. **Given** `--html` без `--narrative` **When** запускается `main` **Then** `request_narrative` не вызван ни разу.

## 3. Модель представления

Два frozen-dataclass'а, только примитивы (`str/int/bool/None`), без `Path` и объектов `core`:

- `FindingView`: `rule`, `kind`, `severity`, `ok`, `title`, `detail`, `weight`.
- `ReportView`: `spec_id`, `spec_title`, `target`, `score`, `max_score`, `passed`, `failed`, `blockers`, `exit_code`, `findings: tuple[FindingView, ...]`, `warnings: tuple[str, ...]`, `narrative: str | None`, `narrative_error: str | None`.

Решения:

- **`passed`/`failed`/`blockers` — числа**, а не списки: UI не пересчитывает вердикт, а `len(findings)` равен `passed + failed`.
- **`findings` — все находки** в порядке правил рубрики. Лимит `--max-findings` к модели и HTML не применяется; JSON тоже уже отдаёт все находки, так что «HTML = JSON» выполняется буквально.
- **`generated_at` отсутствует.** Конституция IV: одинаковый вход → байт-идентичный файл. Время, случайные id и `hash()` запрещены; дата не добавляется никаким флагом в этой итерации.
- **`narrative` не обрезается**: HTML показывает тот же текст, что JSON; иначе ломается сверка и теряется часть рецензии.
- **Порядок по умолчанию — порядок рубрики**; сортировка — клиентская функция UI.
- **Инварианты**: `0 <= score <= max_score`; `passed + failed == len(findings)`; `blockers <= failed`; `exit_code == Report.exit_code` и принимает только 0/1/2 (3 живёт на уровне CLI, не в отчёте).

## 4. Python-контракт

Новый модуль `src/rubrica/report_html.py`. Только stdlib (`dataclasses`, `html`, `os`, `tempfile`, `pathlib`). Импортирует `Report`/`Finding` из `.core` только для чтения; не импортирует `narrative`, `validate`, `urllib`, `socket`. `core.audit()` и `core.Report` не меняются.

```python
class ExportRejected(Exception):
    """HTML-отчёт не создан; сообщение называет путь и причину."""
    def __init__(self, message: str, *, path: str | None = None) -> None: ...

def build_view(report: Report, *, narrative: str | None = None,
               narrative_error: str | None = None) -> ReportView: ...

def render_html(view: ReportView) -> str: ...          # чистая функция, без I/O

def resolve_output_path(raw: str | Path) -> Path: ...  # ранняя валидация пути

def write_atomic(path: Path, text: str) -> None: ...   # temp + os.replace

def export_html(report: Report, raw_path: str | Path, *,
                narrative: str | None = None,
                narrative_error: str | None = None) -> Path: ...
```

- `export_html` — единственная точка входа для CLI: `resolve_output_path` → `build_view` → `render_html` → `write_atomic`; возвращает абсолютный `Path`.
- `build_view` не мутирует `Report`; `render_html` не бросает `ExportRejected`: ошибка шаблона — баг, а не отказ пользователю.
- `resolve_output_path` не принимает `target`: аудит ещё не запущен, проверяются только свойства самого пути.
- Валидирует путь `report_html`, а не `validate.py`: `validate.py` — фича A, её контракт и тесты не трогаем.
- Порядок в `main()`: `validate_all` → (если задан `--html`) `resolve_output_path` → `load_spec` → `audit` → narrative → печать stdout → (если задан `--html`) `export_html`. Повторная валидация пути внутри `export_html` идемпотентна и дешёва.
- `main()` меняет только: `--html` в парсере, ранний `resolve_output_path`, вызов `export_html`, печать `HTML-отчёт: <абсолютный путь>` в stderr, маппинг `ExportRejected` в код 2.

## 5. Алгоритм и инварианты

1. `export_html`: пустой/пробельный `raw_path` → `ExportRejected`.
2. `resolve_output_path`: `expanduser()` → расширение `.html`/`.htm` → это не существующий каталог → `parent` существует и является каталогом → целевой файл не симлинк → вернуть абсолютный `Path` (родитель `resolve()`, имя файла как введено, относительный путь — от текущего каталога).
3. `build_view`: счётчики из `Report`, копия **всех** находок, `warnings` как есть, `narrative`/`narrative_error` без изменений.
4. `render_html`: один `str` из константного каркаса и экранированных значений; UTF-8, переводы строк `\n`, завершающий `\n`.
5. `write_atomic`: `tempfile.mkstemp(dir=parent, prefix=f".{name}.", suffix=".tmp")` → запись → `flush` → `os.fsync` → `os.replace(tmp, path)`; права результата `0600`; при `OSError` удалить temp (best effort) и бросить `ExportRejected` с `strerror`.

Инварианты:

- `core.audit()` и `core.Report` не меняются; `report_html` не мутирует `Report`.
- В `report_html` нет сетевых вызовов; сеть — только `narrative.py` и только при `--narrative`.
- `render_html(view) == render_html(view)` побайтово: нет времени, случайности, `hash()` и переменных окружения.
- Ошибка рендера/записи не меняет баллы и вердикт: stdout уже напечатан, меняется только код на 2.
- При ошибке целевой файл не изменён; temp не остался; частичного HTML не существует.

## 6. Правила пути `--html PATH`

| Случай | Решение |
|---|---|
| пустая строка / пробелы | отказ: `--html: путь не указан` |
| `~` в начале | раскрывается `expanduser()` |
| расширение не `.html`/`.htm` | отказ: нужен `.html` или `.htm` |
| путь указывает на существующий каталог | отказ: нужен файл |
| родительская папка не существует | отказ; каталоги не создаём |
| родитель — не каталог | отказ |
| целевой файл — символическая ссылка | отказ: «укажите реальный путь» |
| символическая ссылка в родительских папках | допустима, родитель приводится к `resolve()` |
| существующий обычный файл | перезапись разрешена, атомарно |
| нет прав на запись | `ExportRejected` после `OSError`, файл не создан |
| путь внутри `target` | разрешён как явное намерение; при повторном аудите файл может попасть под `dir_count` |
| пробелы в пути отчёта | разрешены (в отличие от `target`) — осознанное расхождение |
| относительный путь | от текущего каталога; в stderr и в view — абсолютный |
| права результата | `0600`; отчёт может содержать имена файлов с секретами |

Любой отказ → `ExportRejected` → `ОТКАЗ: HTML-отчёт не записан — <причина>` в stderr и код **2**; аудит до этого не запускается.

Примечание: черновик UI (§2) допускал путь без расширения «как есть». Общий контракт это отменяет: расширение обязательно, `.html` не дописывается молча.

## 7. Безопасность

- Каждая динамическая строка (`target`, `spec_title`, `title`, `detail`, `warnings`, `narrative`, `narrative_error`) проходит `html.escape(s, quote=True)`.
- Динамические строки **не попадают в атрибуты**, кроме разрешённого контрактом `data-search` — он заполняется тем же `html.escape(quote=True)`, поэтому кавычка не разрывает атрибут. Остальные атрибуты контролируемые: `data-severity` ∈ {blocker, major, minor}, `data-ok` ∈ {true, false}, `data-weight` — целое.
- Запрещены `<link>`, `<script src=...>`, `<img src=...>`, `@import`, `url(...)` в CSS, `fetch`/XHR, любые `http://`/`https://` в разметке. Тест проверяет отсутствие этих конструкций; URL-подобный текст из находок остаётся экранированным текстом.
- CSP: `default-src 'none'; style-src 'unsafe-inline'; script-src 'unsafe-inline'; img-src data:`.
- `<meta charset="utf-8">`, `<html lang="ru">`, `<meta name="viewport">`; файл открывается по `file://` без сервера.
- Лимиты: ≤ 200 правил в рубрике, `--max-findings` ≤ 500 (только stdout), рецензия не ограничивается на нашей стороне; ожидаемый размер файла — единицы МБ при худшем входе.
- Значения токенов в HTML не выводятся: `core` сообщает только имена файлов. Рекомендация UI/пользователю: писать отчёт вне `target`, чтобы он не попадал в сдачу.

## 8. Коды возврата и взаимодействие с флагами

| Ситуация | Код |
|---|---|
| аудит 0/1/2, HTML записан | код аудита (0/1/2) |
| аудит 0/1/2, `--narrative` не удался, HTML записан | 3 (текущее поведение, в т.ч. при вердикте 2) |
| путь `--html` отклонён до аудита | 2, аудит не запускается |
| ошибка записи после аудита | 2, отчёт аудита уже напечатан |
| ошибка записи и недоступная рецензия одновременно | 2 (ошибка экспорта важнее) |

- HTML пишется **и при проваленном аудите**: отчёт нужнее всего тогда.
- `--json` + `--html`: stdout — прежний JSON, новых полей (`html`, `html_error`) нет.
- `--html` без `--narrative`: в сеть не ходим, `narrative`/`narrative_error` равны `None`, блок рецензии не выводится.
- `--narrative` + `--html` при отказе зависимости: HTML всё равно пишется, `narrative=None`, `narrative_error` заполнен; код 3.
- Успех: в stderr ровно одна строка `HTML-отчёт: <абсолютный путь>`; stdout не меняется (текст или JSON — как без флага).
- Ошибка экспорта: аудит уже напечатан; в stderr — сообщение с путём и причиной; код 2.

Примечание: черновик UI (FR-UI-019) предлагал «код 3 только при вердикте 0/1, при блокере 2». Контракт сохраняет текущее поведение `cli.py`: `exit_code` заменяется на 3 при недоступной рецензии независимо от вердикта. Менять `cli.py` в этой части нельзя.

## 9. Требования, критерии, допущения

- **FR-LOG-001**: `build_view` строит `ReportView` из `Report` без мутации.
- **FR-LOG-002**: `score`, `max_score`, `passed`, `failed`, `blockers`, `exit_code` в view равны значениям `Report`.
- **FR-LOG-003**: порядок находок в view совпадает с порядком рубрики.
- **FR-LOG-004**: view и HTML содержат все находки; `max_findings` в них не участвует.
- **FR-LOG-005**: `render_html` чиста и детерминирована; `generated_at` отсутствует.
- **FR-LOG-006**: в HTML нет внешних CSS/JS/шрифтов/картинок и URL-ресурсов.
- **FR-LOG-007**: все динамические строки экранированы; `data-search` экранируется как значение атрибута.
- **FR-LOG-008**: запись атомарна, права `0600`, при ошибке целевой файл не меняется, temp удалён.
- **FR-LOG-009**: `ExportRejected` для пустого пути, неверного расширения, каталога, отсутствующего/некаталогового родителя, симлинка, ошибок ОС.
- **FR-LOG-010**: ошибка экспорта → код 2, аудит не пересчитывается; 2 приоритетнее 3.
- **FR-LOG-011**: `resolve_output_path` — после `validate_all`, до `load_spec`/`audit`.
- **FR-LOG-012**: без `--html` поведение и коды не меняются; без `--narrative` сеть не используется.
- **FR-LOG-013**: `core.py`, `validate.py`, `spec.py`, `narrative.py` не изменяются; новых зависимостей нет.
- **FR-LOG-014**: `narrative` передаётся в HTML без обрезки и совпадает с JSON.
- **FR-LOG-015**: `exit_code` в модели — только 0/1/2; 3 формируется в CLI, но не попадает в метрики отчёта.
- **SC-LOG-001**: два прогона на одном входе дают идентичные байты файла.
- **SC-LOG-002**: HTML проходит проверку «нет внешних ресурсов» и открывается по `file://`.
- **SC-LOG-003**: все существующие тесты зелёные, `sh scripts/check.sh` проходит.
- **SC-LOG-004**: ни один сценарий отказа пути не создаёт файл и не оставляет `.tmp`.
- **SC-LOG-005**: score/max, passed/failed/blockers и множество rule id в HTML совпадают с JSON того же запуска.
- **SC-LOG-006**: файл с 200 находками и рецензией произвольной длины строится без обрезки данных.

**Допущения**: путь отчёта задаётся явно (дефолтных имён нет); локаль и часовой пояс не влияют на вывод; `target` — уже разрешённый абсолютный путь (как в тексте/JSON); поиск, фильтр severity, «только провалы», сортировку и сброс UI реализует на клиенте по данным разметки.

## 10. План проверок

1. `build_view`: счётчики, все находки, порядок, отсутствие мутации (`as_dict()` до/после), отсутствие `hidden_findings`/`generated_at`, `narrative` без обрезки.
2. `render_html`: экранирование `<script>` и `"><img onerror=...>` в `detail`; отсутствие `<link`, `src=`, `@import`, `url(`, `http://`; наличие `charset=utf-8`; пустой список находок рендерится без ошибок.
3. `export_html`: файл создан, путь абсолютный; перезапись работает; нет родителя / `.txt` и без расширения / каталог / симлинк → `ExportRejected`; права `0600`.
4. Атомарность: подменить `os.replace` на бросающий `OSError` — старый файл цел, temp удалён.
5. CLI e2e через `main()`: `--html` для pass/fail/blocker; `--html --json` (stdout парсится, поля прежние, файл есть); `--html --max-findings 1` (stdout урезан, HTML полный); `--html --narrative` с замоканным `NarrativeUnavailable` при вердикте 0 и при блокере (код 3, файл есть, баллы прежние).
6. Порядок: при плохом `--html` и валидной сдаче `audit` не вызван (mock), код 2.
7. Детерминизм: два запуска `main` в разное время → одинаковые байты.
8. Без сети: `request_narrative` не вызван без `--narrative`; в `report_html` нет импортов сетевых модулей.
9. Регрессия: существующие 74 теста без изменений.

3. **Валидация пути** — §2: `resolve_output_path` после `validate_all`, до `load_spec`/`audit`; родительские папки не создаются; расширение обязательно.
4. **Ошибка записи** — §2 и §4: атомарная замена, старый файл цел, stdout аудита сохраняется, код 2.
5. **Детерминизм и экранирование** — §3 (нет `generated_at`) и §5 (escape на слое HTML, `data-search`).

## 12. Изменения после согласования

1. **Лимит находок**: было `build_view(report, max_findings=...)`, `hidden_findings` и обрезка HTML → стало «все находки, лимит только у stdout» → почему: HTML обязан совпадать с JSON, иначе сверка и поиск по отчёту врут.
2. **Рецензия**: было обрезание `narrative` до 20 000 символов → стало без обрезки → почему: «HTML = JSON» и невозможность тихо терять часть ответа.
3. **`generated_at`**: был открытый вопрос и условный флаг `--html-date` → стало «поля нет и флага нет» → почему: детерминизм зафиксирован контрактом, лишний флаг вне объёма фичи.
4. **Путь**: было `resolve_output_path(raw, *, target)` без явного правила расширения → стало `resolve_output_path(raw)` с обязательным `.html`/`.htm` → почему: сигнатура из контракта, отказ от «дописать расширение молча».
5. **Порядок вызовов**: было «валидация пути до `audit()`» без привязки к `validate_all` → стало строго после `validate_all` и до `load_spec`/`audit` → почему: ошибки target/spec должны иметь приоритет, но плохой путь не должен запускать чтение сдачи.
6. **Атрибуты**: было «динамические строки вообще не в атрибутах» → стало «плюс `data-search` с экранированием» → почему: UI нужен быстрый поиск, контракт разрешает ровно это исключение.
7. **Код 3**: было неявное «2 приоритетнее 3» без правила для блокера → стало «3 сохраняется как в текущем `cli.py`, в т.ч. при вердикте 2; 2 только при ошибке экспорта» → почему: не менять существующее поведение и не ломать тесты.
8. **Права файла**: было решение вскользь (`0600` от `mkstemp`) → стало явное требование контракта → почему: отчёт может содержать имена файлов с секретами, режим не должен зависеть от umask.
