# Спецификация (до кода) — слой логики HTML-отчёта

**Фича**: `specs/001-html-report/spec.md` — флаг `--html PATH` в CLI `rubrica`
**Команда**: 2 (логика/данные), независимо от команды UI
**Дата**: 2026-11-02 · **Статус**: Draft, до согласования с UI и до реализации

Границы: модель представления, функции, валидация пути, алгоритм рендера и атомарной записи, детерминизм, безопасность, коды возврата. Экранные состояния, тексты и конкретные контролы — зона команды UI; здесь фиксируются только требования к данным, которые она получает.

## 1. Пользовательские истории

### US-LOG-1 (P1) — получить модель отчёта, пригодную для любого рендера

Как вызывающий код (CLI, тест, будущий MCP), я хочу получить из `Report` одну неизменяемую view model, чтобы HTML-рендер не знал о внутренностях `audit()` и не мог исказить вердикт.

**Ценность**: баллы, счётчики и находки берутся из того же `Report`, что и текст/JSON, — расхождений быть не может. **Проверка**: `build_view()` на собранном `Report` даёт ожидаемые счётчики и порядок и не меняет сам `Report`.

1. **Given** отчёт из 3 правил (2 pass, 1 fail, без blocker) **When** вызывается `build_view(report, max_findings=200)` **Then** `score=2`, `max_score=3`, `passed=2`, `failed=1`, `blockers=0`, `exit_code=1`, 3 находки по порядку рубрики.
2. **Given** 5 находок и `max_findings=3` **When** строится view **Then** в `findings` первые 3, `hidden_findings=2`.
3. **Given** `report.warnings` **When** строится view **Then** предупреждения попадают в view в исходном порядке и без изменений.

### US-LOG-2 (P2) — безопасно записать автономный HTML-файл

Как пользователь, указавший `--html out/audit.html`, я хочу получить один самодостаточный файл, который открывается офлайн и не превращает недоверенную папку сдачи в вектор инъекции.

**Ценность**: артефакт можно приложить к сдаче; ошибка записи не оставляет «полуфайл» и не портит существующий отчёт. **Проверка**: `export_html()` пишет файл, повторный запуск даёт байт-в-байт тот же результат, при падении записи старый файл не меняется.

1. **Given** валидный view и путь `tmp/out/report.html` с существующей папкой **When** вызывается `export_html(...)` **Then** файл существует, начинается с `<!DOCTYPE html>`, содержит `<meta charset="utf-8">`, возвращён `Path`.
2. **Given** существующий `report.html` с содержимым `OLD` **When** запись падает **Then** файл по-прежнему содержит `OLD`, temp-файлов не осталось.
3. **Given** путь `report.txt` **When** вызывается экспорт **Then** `ExportRejected` с текстом про допустимое расширение `.html`.

### US-LOG-3 (P3) — не сломать существующий аудит

Как мейнтейнер, я хочу, чтобы без `--html` stdout, JSON и коды возврата остались прежними, а `core.py` по-прежнему не знал ни о рендере, ни о сети.

**Ценность**: фича аддитивна; 74 существующих теста и контракт не меняются. **Проверка**: `main` без `--html` даёт прежний stdout и код; `report_html` не импортирует `urllib`/`socket`; `core.py` не меняется.

1. **Given** сдача без `README.md` и blocker в рубрике **When** `main` без `--html` **Then** код 2, `ОТКАЗ` в stderr, файлов не создано.
2. **Given** та же сдача **When** `main` с `--html /nope/report.html` **Then** аудит печатается как раньше, затем код 2 и `ОТКАЗ` в stderr.
3. **Given** `--html` без `--narrative` **When** запускается `main` **Then** `request_narrative` не вызван ни разу.

## 2. Модель представления

Два frozen-dataclass'а, только примитивы (`str/int/bool/None`), без `Path` и объектов `core`:

- `FindingView`: `rule`, `kind`, `severity`, `ok`, `title`, `detail`, `weight`.
- `ReportView`: `spec_id`, `spec_title`, `target`, `score`, `max_score`, `passed`, `failed`, `blockers`, `exit_code`, `findings: tuple[FindingView, ...]`, `hidden_findings: int`, `warnings: tuple[str, ...]`, `narrative: str | None`, `narrative_error: str | None`.

Решения:

- **`passed`/`failed`/`blockers` — числа**, а не списки: UI не пересчитывает вердикт, а длина `findings` после лимита не равна `failed`.
- **`hidden_findings`** — сколько отрезал `--max-findings`; без него не отличить «всё хорошо» от «показано не всё».
- **`generated_at` отсутствует.** Конституция IV требует воспроизводимости: одинаковый вход → байт-идентичный файл. Время ломает тест на детерминизм и сравнение отчётов в git. Если дата нужна — отдельный флаг `--html-date`, и только тогда поле `generated_at: str | None`.
- **`narrative` обрезается до 20 000 символов** (маркер `…`), т.к. длина ответа endpoint не ограничена, а файл не должен расти бесконтрольно; обрезка — в `build_view`, чтобы рендер остался чистым.
- **Порядок `findings` = порядок правил рубрики**; сортировка — клиентская функция UI, серверный порядок стабилен.
- **Инварианты**: `0 <= score <= max_score`; `passed + failed ==` числу всех находок до лимита; `blockers <= failed`; `exit_code == Report.exit_code`; `max_findings >= 1`.

## 3. Python-контракт

Новый модуль `src/rubrica/report_html.py`. Только stdlib (`dataclasses`, `html`, `os`, `tempfile`, `pathlib`). Импортирует `Report`/`Finding` из `.core` только для чтения; `narrative` и `validate` не импортирует; сетевых модулей нет.

```python
class ExportRejected(Exception):
    """HTML-отчёт не создан. Сообщение называет путь и причину."""
    def __init__(self, message: str, *, path: str | None = None) -> None: ...

def build_view(report: Report, *, max_findings: int = 200,
               narrative: str | None = None,
               narrative_error: str | None = None) -> ReportView: ...

def render_html(view: ReportView) -> str: ...   # чистая функция, без I/O

def resolve_output_path(raw: str | Path, *, target: str | Path) -> Path: ...

def write_atomic(path: Path, text: str) -> None: ...  # только после resolve

def export_html(report: Report, raw_path: str | Path, *,
                max_findings: int = 200,
                narrative: str | None = None,
                narrative_error: str | None = None) -> Path: ...
```

- `build_view` не бросает исключений на валидном `Report`; `max_findings < 1` → `ValueError` (программная ошибка; CLI отсекает её в `validate_flags`). `render_html` не бросает `ExportRejected`: ошибка шаблона — баг, не отказ.
- `export_html` — единственная точка для CLI: `resolve_output_path` → `build_view` → `render_html` → `write_atomic`.
- `resolve_output_path` вызывается **до** `audit()` (плохой путь не должен запускать чтение сдачи), `write_atomic` — **после** (нужен готовый отчёт).
- Путь валидирует `report_html`, а не `validate.py`: `validate.py` — фича A, её контракт и тесты не трогаем. CLI ловит `ExportRejected` и печатает `ОТКАЗ: HTML-отчёт не записан — <reason>`.
- `main()` меняет только: `--html` в парсере, ранний `resolve_output_path`, вызов `export_html` после `audit`, маппинг исключения в код 2.

## 4. Алгоритм и инварианты

1. `export_html`: пустой/пробельный `raw_path` → `ExportRejected`.
2. `resolve_output_path`: `expanduser()` → расширение → не существующий каталог → `parent` существует и каталог → целевой файл не симлинк → вернуть `Path` (родитель `resolve()`, имя файла как введено).
3. `build_view`: счётчики из `Report`, копия первых `max_findings` находок, `hidden_findings = max(0, len(all) - len(shown))`, обрезка `narrative`.
4. `render_html`: один `str` из константного каркаса и экранированных значений; UTF-8, переводы строк `\n`, завершающий `\n`.
5. `write_atomic`: `tempfile.mkstemp(dir=parent, prefix=f".{name}.", suffix=".tmp")` → запись → `flush` → `os.fsync` → `os.replace(tmp, path)`; при `OSError` удалить temp (best effort) и бросить `ExportRejected` с `strerror`.

Инварианты:

- `core.audit()` и `core.Report` не меняются; `report_html` не мутирует `Report`.
- В `report_html` нет сетевых вызовов; сеть — только `narrative.py` и только при `--narrative`.
- `render_html(view) == render_html(view)` побайтово: нет времени, случайности, `hash()` и переменных окружения.
- Ошибка рендера/записи не меняет баллы и вердикт: stdout уже напечатан, меняется только код на 2.
- При ошибке целевой файл не изменён; temp не остался.

## 5. Правила пути `--html PATH`

| Случай | Решение |
|---|---|
| пустая строка / пробелы | отказ: «--html: путь не указан» |
| `~` в начале | раскрывается `expanduser()` |
| расширение не `.html`/`.htm` | отказ с перечислением допустимых |
| существующий каталог | отказ: «это каталог, нужен файл» |
| нет родительской папки | отказ; каталоги не создаём |
| родитель — файл | отказ: «родитель не каталог» |
| нет прав на запись | `ExportRejected` после `OSError`, файл не создан |
| целевой файл — симлинк | отказ: «укажите реальный путь» |
| симлинк в родительских папках | допустим, родитель приводится к `resolve()` |
| файл уже существует | перезапись разрешена, атомарно, без бэкапа |
| путь внутри `target` | разрешён как явное намерение; при повторном аудите файл может попасть под `dir_count` |
| пробелы в пути отчёта | разрешены (в отличие от `target`) — осознанное расхождение |
| права результата | `0600` от `mkstemp`; отчёт может содержать имена файлов с секретами |

Любой отказ → `ExportRejected` → `ОТКАЗ` в stderr и код **2**.

## 6. Безопасность

- Каждая динамическая строка (`target`, `spec_title`, `title`, `detail`, `warnings`, `narrative`, `narrative_error`) проходит `html.escape(s, quote=True)`.
- Динамические строки **не попадают в атрибуты**. Атрибуты только из контролируемых значений: `data-severity` ∈ {blocker, major, minor}, `data-ok` ∈ {true, false}, `data-weight` — целое. Инъекция в атрибут исключена по построению.
- Запрещены `<link>`, `<script src=...>`, `<img src=...>`, `@import`, `url(...)` в CSS, любые `http://`/`https://` в разметке. Тест проверяет отсутствие этих конструкций; URL-подобный текст из находок остаётся экранированным текстом.
- CSP: `<meta http-equiv="Content-Security-Policy" content="default-src 'none'; style-src 'unsafe-inline'; script-src 'unsafe-inline'; img-src data:">` — страховка на случай будущих правок разметки.
- `<meta charset="utf-8">`, `lang="ru"`; файл открывается офлайн без сервера.
- Лимиты: ≤ 200 правил, `--max-findings` ≤ 500, `narrative` ≤ 20 000 символов; ожидаемый размер файла < 2 МБ.
- Значения токенов в HTML не выводятся: `core` сообщает только имена файлов. Рекомендация: писать отчёт вне `target`, чтобы он не попадал в сдачу.

## 7. Коды возврата и взаимодействие с флагами

| Ситуация | Код |
|---|---|
| аудит 0/1/2, экспорт успешен | код аудита (0/1/2) |
| аудит 0/1, `--narrative` упал, экспорт успешен | 3 |
| путь отклонён / рендер / запись упали | 2 (приоритет над 3) |
| аудит 2 (blocker) и экспорт упал | 2 |

- HTML пишется **и при проваленном аудите**: отчёт нужнее всего тогда.
- `--json` + `--html`: JSON в stdout не меняется и **не получает** новых полей (`html`, `html_error`) — публичный формат не расширяем.
- `--html` без `--narrative`: в сеть не ходим, `narrative`/`narrative_error` равны `None`, блок рецензии не выводится.
- `--narrative` + `--html` при отказе зависимости: HTML всё равно пишется, `narrative=None`, `narrative_error` заполнен; код 3.
- Ошибка экспорта: аудит уже напечатан; в stderr одна строка `ОТКАЗ: HTML-отчёт не записан — <причина>`; код 2.

## 8. Требования, критерии, допущения

- **FR-LOG-001**: `build_view` строит `ReportView` из `Report` без мутации.
- **FR-LOG-002**: `score`, `max_score`, `passed`, `failed`, `blockers`, `exit_code` в view равны значениям `Report`.
- **FR-LOG-003**: порядок находок в view совпадает с порядком рубрики.
- **FR-LOG-004**: `--max-findings` ограничивает `findings` и заполняет `hidden_findings`.
- **FR-LOG-005**: `render_html` чиста; одинаковый view → идентичная строка.
- **FR-LOG-006**: в HTML нет внешних CSS/JS/шрифтов/картинок и URL-ресурсов.
- **FR-LOG-007**: все динамические строки экранированы `html.escape`.
- **FR-LOG-008**: запись атомарна; при ошибке целевой файл не меняется.
- **FR-LOG-009**: `ExportRejected` для пустого пути, неверного расширения, каталога, отсутствующего родителя, симлинка, ошибок ОС.
- **FR-LOG-010**: ошибка экспорта → код 2, аудит не пересчитывается.
- **FR-LOG-011**: без `--html` поведение и коды не меняются; без `--narrative` сеть не используется.
- **FR-LOG-012**: `core.py`, `validate.py`, `spec.py`, `narrative.py` не изменяются; новых зависимостей нет.
- **SC-LOG-001**: два прогона на одном входе дают идентичные байты файла.
- **SC-LOG-002**: HTML проходит проверку «нет внешних ресурсов» и открывается офлайн.
- **SC-LOG-003**: все существующие тесты зелёные, `sh scripts/check.sh` проходит.
- **SC-LOG-004**: ни один сценарий отказа пути не создаёт файл и не оставляет `.tmp`.
- **SC-LOG-005**: 200 находок + рецензия 20 000 символов укладываются в 2 МБ.

**Допущения**: путь отчёта задаётся явно (дефолтных имён нет); локаль и часовой пояс не влияют на вывод; `target` — уже разрешённый абсолютный путь (как в тексте/JSON); поиск, фильтр severity, «только провалы», сортировку и сброс UI реализует на клиенте по данным разметки.

## 9. План проверок

1. `build_view`: счётчики, лимит и `hidden_findings`, порядок, обрезка narrative, отсутствие мутации (`as_dict()` до/после).
2. `render_html`: экранирование `<script>` и кавычек в `detail`; отсутствие `<link`, `src=`, `@import`, `url(`, `http://`; наличие `charset=utf-8`; пустой список находок рендерится без ошибок.
3. `export_html`: файл создан, путь возвращён; перезапись работает; нет родителя / `.txt` / каталог / симлинк → `ExportRejected`.
4. Атомарность: подменить `os.replace` на бросающий `OSError` — старый файл цел, temp удалён.
5. CLI e2e через `main()`: `--html` для pass/fail/blocker; `--html --json` (stdout парсится, файл есть); `--html --narrative` с замоканным `NarrativeUnavailable` (код 3, файл есть, `narrative_error` в HTML).
6. Детерминизм: два запуска `main` в разное время → одинаковые байты.
7. Без сети: `request_narrative` не вызван без `--narrative`; в `report_html` нет импортов сетевых модулей.
8. Регрессия: существующие 74 теста без изменений.

## 10. Вопросы команде UI

1. Нужен ли `generated_at` в шапке? Он ломает байтовую воспроизводимость; если нужен — включаем только по флагу `--html-date`.
2. Как показывать `hidden_findings > 0`: строкой «скрыто N по лимиту», счётчиком или блокировкой поиска по скрытым находкам?
3. Какая сортировка по умолчанию: порядок рубрики, severity (blocker→minor) или «сначала провалы»? От этого зависит необходимость ключа `data-order`.
4. Что показывать при «только провалы» и нуле провалов — пустой список, сообщение или автосброс фильтра?
5. Показывать ли `narrative_error` целиком или короткую пометку «рецензия недоступна»?
