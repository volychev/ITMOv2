# UI-спецификация: автономный HTML-отчёт `rubrica --html`

**Фича**: [`001-html-report`](../../spec.md)
**Команда**: UI (наблюдаемое поведение CLI и экрана)
**Дата**: 2026-11-02
**Статус**: Draft — до согласования с командой логики
**Границы**: только CLI-поверхность, экран, состояния и сквозные сценарии. Внутренние функции, структуры данных и алгоритм записи — зона команды логики.

## 1. Пользовательские истории

### US-1 — Сгенерировать HTML-отчёт (P1)

Студент или преподаватель запускает аудит и получает один файл, который можно открыть офлайн и показать рядом с работой.

**Ценность**: отчёт переживает терминал, копируется в чат/архив и одинаково выглядит у всех.
**Независимая проверка**: запустить `rubrica <target> --html /tmp/report.html` на валидной сдаче, открыть файл в браузере без сети и сверить баллы и находки с `--json`.

**Сценарии**:
1. **Given** валидная папка сдачи и валидная рубрика, **When** запускаю `rubrica <target> --html /tmp/report.html`, **Then** создаётся `/tmp/report.html`, в stdout печатается обычный текстовый отчёт, в stderr — одна строка `HTML-отчёт: /tmp/report.html`, код возврата совпадает с запуском без флага.
2. **Given** сдача с провалами, **When** генерирую HTML, **Then** баллы, `passed/failed/blockers`, находки и предупреждения в HTML совпадают с JSON-отчётом того же запуска.
3. **Given** путь `--html /nonexistent-dir/report.html` без родительской папки, **When** запускаю команду, **Then** ни один файл не создаётся, в stderr есть сообщение с путём и причиной, код возврата 2.

### US-2 — Найти и отфильтровать находки (P2)

Человек открывает отчёт, чтобы быстро ответить: «что именно провалено и где».

**Ценность**: не приходится глазами искать по длинному списку из 200 правил.
**Независимая проверка**: открыть отчёт с ≥ 5 находками, ввести запрос, переключить severity, включить «только провалы», сменить сортировку и нажать «Сбросить».

**Сценарии**:
1. **Given** отчёт открыт, **When** ввожу `readme` в поиск, **Then** остаются только находки, где `readme` встречается в rule id, заголовке или деталях без учёта регистра; счётчик показывает `Показано N из M`.
2. **Given** выбрано `severity=blocker` и включено «только провалы», **When** смотрю список, **Then** в нём только проваленные находки severity `blocker`; фильтры применяются совместно (AND).
3. **Given** активны фильтры, **When** нажимаю «Сбросить», **Then** поиск пуст, severity `все`, «только провалы» выключено, сортировка «порядок рубрики», список снова показывает все находки.
4. **Given** фильтры не дают совпадений, **When** список пуст, **Then** показано понятное пустое состояние и доступна кнопка сброса; итоговые баллы в шапке не меняются.

### US-3 — Понять состояние аудита (P3)

Человек должен за секунду увидеть вердикт, а не вычислять его из списка.

**Ценность**: ошибка «сдал с блокером» и деградация рецензии заметны сразу.
**Независимая проверка**: сгенерировать HTML для трёх сдач (всё прошло, провалы без блокера, блокер) и для отказа рецензии; сверить баннеры и коды возврата.

**Сценарии**:
1. **Given** все правила прошли, **When** открываю HTML, **Then** виден зелёный вердикт «Все правила пройдены», `failed=0`, `blockers=0`, код аудита 0.
2. **Given** есть провалы без `blocker`, **When** открываю HTML, **Then** вердикт «Есть провалы без блокеров», код аудита 1; блокеры не показаны.
3. **Given** есть провал `severity=blocker`, **When** открываю HTML, **Then** вердикт «Есть блокирующие провалы», блокирующие находки визуально выделены, код аудита 2.
4. **Given** `--narrative` запрошен, но endpoint недоступен, **When** открываю HTML, **Then** виден блок «Рецензия недоступна» с текстом ошибки и пометкой, что результат аудита не изменён; код возврата процесса 3, баллы прежние.

## 2. CLI-контракт

```text
rubrica <target> [--spec PATH] [--json] [--max-findings N] [--narrative]
                 [--model ID] [--timeout SECONDS] [--html PATH]
```

`--html PATH` — необязательный экспорт. Это не режим вывода, а дополнительный артефакт: stdout не меняется.

| Комбинация | Поведение |
|---|---|
| `--html PATH` | Текст в stdout как без флага; HTML записан; подтверждение в stderr. |
| `--html PATH --json` | Разрешено. В stdout — только валидный JSON (схема и поля не меняются); HTML — отдельный файл; подтверждение в stderr. |
| `--html PATH --narrative` | Рецензия или её ошибка попадает в HTML так же, как в JSON-поля `narrative` / `narrative_error`. |
| `--html PATH --max-findings N` | `--max-findings` по-прежнему ограничивает только текстовый stdout; HTML содержит все находки отчёта. |
| `--html PATH --spec PATH` | В HTML попадают id/title/правила именно этой рубрики; при невалидной рубрике файл не создаётся, код 2. |
| `--html ""` | Отказ до аудита, код 2, файл не создаётся. |
| Без `--html` | Поведение полностью прежнее. |

**stdout**: байт-в-байт прежний текстовый или JSON-отчёт. Никаких новых полей и строк.
**stderr**:
- при успешной записи — ровно одна строка `HTML-отчёт: <абсолютный путь>`;
- при ошибке — сообщение, называющее флаг, путь и причину;
- ошибки рецензии не дублируются в stderr: они остаются в JSON и в HTML.

**Коды возврата**:
- `0` — все правила прошли, HTML записан;
- `1` — есть провалы без блокеров, HTML записан;
- `2` — блокер; либо отклонён вход/рубрика/путь `--html`; либо не удалось записать HTML;
- `3` — аудит дал 0 или 1, HTML записан, но рецензия недоступна.

Приоритет: отказ входа/рубрики/пути и ошибка записи важнее вердикта; `3` не перекрывает `2`. Если запись HTML не удалась, отчёт аудита всё равно печатается в stdout, но процесс завершается с кодом 2.

**Ошибки пути `--html`**:

| Ситуация | Сообщение (stderr) | Код |
|---|---|---:|
| пустой PATH | `ОТКАЗ: --html: путь не указан` | 2 |
| PATH указывает на каталог | `ОТКАЗ: --html: <path> — это каталог, нужен путь к файлу` | 2 |
| нет родительской папки | `ОТКАЗ: --html: родительская папка <dir> не существует` | 2 |
| нет прав / ошибка записи | `ОШИБКА ЭКСПОРТА HTML: не удалось записать <path>: <причина>` | 2 |
| некорректный путь (например, NUL) | `ОТКАЗ: --html: некорректный путь <path>` | 2 |

Родительские папки не создаются. Существующий файл перезаписывается только при успехе; при любой ошибке прежнее содержимое остаётся нетронутым. Путь без расширения принимается как есть, `.html` не дописывается. Относительный путь разрешается от текущего каталога, в подтверждении печатается абсолютный.

## 3. Экран HTML

Один самодостаточный файл, открывается двойным щелчком, `file://`, без сети.

**Шапка**:
- `<h1>` «Отчёт аудита rubrica»;
- `spec id · spec title` (экранированные);
- цель аудита — путь папки сдачи;
- метрики: `Баллы: P/M`, `Пройдено: p`, `Провалено: f`, `Блокеров: b`, `Код аудита: 0|1|2`;
- вердикт-баннер: «Все правила пройдены» / «Есть провалы без блокеров» / «Есть блокирующие провалы»;
- отдельный бейдж «Рецензия недоступна», если `--narrative` не удался.

**Панель действий** (над списком):
- поиск `type=search`, подпись «Поиск по находкам», подсказка «rule id, заголовок или детали»;
- селект «Severity»: `все`, `blocker`, `major`, `minor`;
- чекбокс «Только провалы»;
- селект «Сортировка»: `порядок рубрики` (по умолчанию), `провалы сначала`, `severity: blocker → minor`, `rule id`, `вес: больше сначала`;
- кнопка «Сбросить»;
- счётчик `Показано N из M` с `aria-live="polite"`.

Поиск — регистронезависимая подстрока (Unicode casefold) по rule id, заголовку и деталям; ведущие/хвостовые пробелы отбрасываются. Фильтры и поиск комбинируются по AND. Сортировка устойчивая: при равенстве сохраняется порядок рубрики. Ввод в поиск применяется сразу, без перезагрузки страницы и без кнопки «Применить».

**Список находок** — секция «Находки», по элементу на находку:
- текстовый статус `PASS` / `FAIL` (не только цвет);
- бейдж severity: `blocker` / `major` / `minor`;
- rule id в `<code>`;
- заголовок правила;
- детали проверки;
- вес: `вес: N`.

**Предупреждения** — секция «Предупреждения» со счётчиком; каждый пункт отдельной строкой; если пусто — «Предупреждений нет».

**Рецензия** — секция «Рецензия», три состояния:
- `--narrative` не передан: «Рецензия не запрашивалась»;
- рецензия получена: экранированный текст с сохранением переводов строк, без Markdown и без вставки HTML;
- рецензия недоступна: «Рецензия недоступна: <narrative_error>» и фраза «Результат аудита не изменён».

**Подвал**: `rubrica · <spec_id>`. Даты и времени генерации нет.

## 4. Состояния и пустые состояния

| Состояние | Что видно | Код |
|---|---|---:|
| Все правила прошли | зелёный баннер, `Провалено: 0`, все находки `PASS` | 0 |
| Провалы без blocker | жёлтый баннер, провалы в списке | 1 |
| Есть blocker | красный баннер, блокирующие находки выделены | 2 |
| Рецензия недоступна | бейдж деградации, блок с ошибкой, метрики не меняются | 3 |
| Нет совпадений после фильтра | «Ничего не найдено. Измените запрос или сбросьте фильтры», `Показано 0 из M`; метрики шапки прежние | как у аудита |
| «Только провалы» при полном успехе | «Провалов нет» | 0 |
| Нет предупреждений | «Предупреждений нет» | — |
| Пустой отчёт (защитный случай) | «Находок нет», `0/0`, без падения страницы | 0 |
| Нет JavaScript | полный список находок и все секции читаются; панель фильтров может быть скрыта, есть пояснение | — |

Ошибки экспорта не создают частичный HTML: либо полный файл, либо прежнее состояние пути. Ошибка записи не отменяет и не искажает вывод аудита.

## 5. Доступность и офлайн

- `<html lang="ru">`, `<meta charset="utf-8">`, `<meta name="viewport">`, осмысленный `<title>`.
- Семантика: `<header>`, `<main>`, `<section aria-labelledby>`, `<h1>/<h2>`, список `<ul>/<li>`; нативные `input`, `select`, `checkbox`, `button`.
- У каждого контрола есть видимая подпись, связанная через `<label for>`; у кнопки — понятное имя.
- Полное управление с клавиатуры: Tab/Shift+Tab, Space для чекбокса, Enter не перезагружает страницу; видимый фокус не менее 2 px.
- Счётчик результатов — `aria-live="polite" aria-atomic="true"`, чтобы изменение озвучивалось.
- Статус и severity передаются текстом, а не только цветом. Контраст текста ≥ 4.5:1, крупного текста и границ ≥ 3:1.
- Все CSS и JS встроены в файл. Нет `<link>`, внешних шрифтов, картинок, `fetch`/XHR и любых сетевых запросов.
- Весь текст из отчёта (id, title, detail, пути, предупреждения, рецензия) считается недоверенным и экранируется; HTML из данных не исполняется.
- Без JS отчёт остаётся полным и читаемым; фильтрация — прогрессивное улучшение.
- Одинаковый отчёт даёт байт-в-байт одинаковый HTML: без времени, случайных id и нестабильного порядка.

## 6. Функциональные требования

- **FR-UI-001**: CLI принимает `--html PATH`; флаг виден в `rubrica --help` с описанием «записать автономный HTML-отчёт».
- **FR-UI-002**: `--html` не меняет stdout и не добавляет полей в JSON.
- **FR-UI-003**: `--html` и `--json` можно использовать вместе; stdout остаётся чистым JSON.
- **FR-UI-004**: при успешной записи в stderr печатается абсолютный путь одной строкой.
- **FR-UI-005**: HTML — один файл с встроенными CSS/JS, без внешних ресурсов.
- **FR-UI-006**: шапка содержит spec id, title, target, score/max, passed, failed, blockers, код аудита и вердикт.
- **FR-UI-007**: список содержит все находки с PASS/FAIL, severity, rule id, заголовком, деталями и весом.
- **FR-UI-008**: предупреждения показаны полностью; пустой список имеет явное состояние.
- **FR-UI-009**: рецензия имеет три состояния: не запрошена, получена, недоступна; ошибка не меняет метрики.
- **FR-UI-010**: поиск фильтрует по rule id, заголовку и деталям без учёта регистра и обновляет счётчик.
- **FR-UI-011**: severity-фильтр и «только провалы» комбинируются по AND.
- **FR-UI-012**: сортировка предлагает порядок рубрики, провалы сначала, severity, rule id и вес; по умолчанию — порядок рубрики.
- **FR-UI-013**: «Сбросить» возвращает все контролы к значениям по умолчанию и показывает все находки.
- **FR-UI-014**: счётчик `Показано N из M` обновляется при каждом изменении фильтров.
- **FR-UI-015**: пустой результат фильтрации показывает понятное сообщение и не скрывает итоговые метрики.
- **FR-UI-016**: пустой PATH, каталог вместо файла и отсутствующая родительская папка отклоняются до записи с кодом 2.
- **FR-UI-017**: ошибка записи даёт код 2, сообщение с путём и причиной; существующий файл не повреждается.
- **FR-UI-018**: при отказе входа/рубрики HTML не создаётся, код 2.
- **FR-UI-019**: при недоступной рецензии код 3 только если вердикт аудита 0 или 1; при блокере остаётся 2.
- **FR-UI-020**: все данные экранируются; рецензия выводится как обычный текст.
- **FR-UI-021**: отчёт использует `lang="ru"`, семантические элементы, подписи и клавиатурную доступность.
- **FR-UI-022**: без JavaScript отчёт читается и содержит все находки.
- **FR-UI-023**: HTML детерминирован для одинакового отчёта и флагов.
- **FR-UI-024**: `--max-findings` не обрезает HTML; ограничение остаётся только у текстового stdout.

## 7. Критерии успеха

- **SC-UI-001**: для 100% запусков с валидным `--html` файл существует, не пуст и открывается в браузере офлайн.
- **SC-UI-002**: 0 сетевых запросов при открытии отчёта (проверка DevTools/Network на `file://`).
- **SC-UI-003**: значения score/max, passed, failed, blockers и список rule id в HTML на 100% совпадают с JSON того же запуска.
- **SC-UI-004**: при 200 находках любое изменение фильтра или сортировки применяется быстрее 100 мс на офисном ноутбуке.
- **SC-UI-005**: клавиатурой доступны все пять контролов и сброс; фокус всегда виден.
- **SC-UI-006**: HTML с недоверенными строками `<script>` и `"><img onerror=...>` не исполняет их и показывает как текст.
- **SC-UI-007**: повторная генерация из одинакового отчёта даёт идентичные байты файла.
- **SC-UI-008**: все сценарии ошибок пути дают код 2, сообщение с путём и не оставляют частичный файл.

## 8. Допущения и границы

- HTML всегда содержит полный отчёт; `--max-findings` остаётся ограничением консольного вывода (см. вопрос 1).
- Путь `--html` не создаёт родительские каталоги; расширение не навязывается.
- Запись внутрь папки сдачи не запрещается: отчёт отражает состояние до экспорта, повторный аудит увидит новый файл.
- Новых зависимостей нет: HTML собирается средствами стандартной библиотеки, CSS/JS — простой встроенный текст.
- Не входит: автооткрытие браузера, локальный сервер, графики, Markdown-рендеринг рецензии, темы, сохранение фильтров между открытиями, локализация, изменение текстового/JSON-формата.
- Поддержка — актуальные Chrome/Firefox/Safari/Edge; IE не поддерживается.
- `--html -` не означает stdout; PATH трактуется как имя файла.

## 9. Вопросы команде логики

1. **Гранулярность и лимит.** Что считается одной находкой в HTML — элемент `Report.findings` как есть? Подтверждаете, что `--max-findings` не режет HTML и порядок по умолчанию — порядок рубрики?
2. **Рецензия и код 3.** Передаются ли в рендер те же `narrative` / `narrative_error`, что в JSON, и считается ли ошибка рецензии нефатальной для экспорта? Сейчас `cli.py` возвращает 3 даже при блокере; фиксируем ли правило «3 только при вердикте 0/1, иначе 2»?
3. **Валидация пути.** Кто и когда проверяет `--html`: до аудита или после? Согласны ли с отказом до аудита для пустого PATH/каталога/отсутствующей родительской папки и с запретом создавать родительские папки?
4. **Ошибка записи.** Нужна ли атомарная замена через временный файл, чтобы старый отчёт не портился? Сохраняем ли печать отчёта в stdout и код 2 при ошибке записи?
5. **Детерминизм и экранирование.** Гарантируете ли байт-в-байт одинаковый HTML при одинаковом отчёте (без timestamp и случайных id) и где проходит граница экранирования недоверенных строк — в общем helper'е или на слое HTML?
