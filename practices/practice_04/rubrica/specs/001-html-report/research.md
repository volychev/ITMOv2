# Research: автономный HTML-отчёт

**Фича**: `001-html-report` · **Дата**: 2026-11-02
**Статус**: все неизвестные закрыты; открытых `NEEDS CLARIFICATION` нет.

## R1. Чем рендерить HTML

**Decision**: собирать строку в Python на стандартной библиотеке; CSS и JS
встроить в тот же файл.

**Rationale**: проект живёт на stdlib + `pyyaml`; конституция IV запрещает
тянуть зависимость ради одной фичи. Отчёт должен открываться офлайн, поэтому
внешние assets исключены по определению.

**Alternatives considered**:
- Jinja2 — удобные шаблоны, но новая зависимость и риск случайного
  экранирования/неэкранирования.
- Отдельные `.css`/`.js` рядом с HTML — нарушает «один файл» и ломает
  копирование отчёта в чат/архив.
- React/Vue c CDN — сеть, сборка, лишний вес; для 200 строк данных избыточно.

## R2. Модель представления

**Decision**: frozen-dataclass `ReportView` и `FindingView` с примитивами;
`build_view(report, *, narrative=None, narrative_error=None)`.

**Rationale**: рендер не должен знать о `Report` и не может случайно изменить
аудит. Явные типы упрощают тесты и фиксируют инварианты. Счётчики берутся из
`Report`, а не пересчитываются по списку.

**Alternatives considered**:
- Передавать `Report` напрямую — рендер связан с ядром, выше риск мутации.
- `dict` — меньше кода, но нет инвариантов и автодополнения; ошибки полей
  всплывают только в тестах.
- `Report.as_dict()` — почти подходит, но добавляет `findings` в формате JSON
  и не фиксирует отсутствие времени/скрытых полей.

## R3. Атомарная запись

**Decision**: `tempfile.mkstemp` в родительской папке → запись UTF-8 →
`flush` → `fsync` → `os.replace`; при `OSError` удалить temp и бросить
`ExportRejected`; права `0600`.

**Rationale**: HTML может перезаписывать существующий отчёт; падение на
середине не должно оставить полуфайл. `os.replace` атомарен в пределах одной
ФС. `0600` не даёт отчёту с именами файлов стать world-readable.

**Alternatives considered**:
- Прямая запись `path.write_text()` — при ошибке портит старый файл.
- Запись в temp в системном `/tmp` + `os.replace` — может быть другая ФС,
  `os.replace` упадёт с `EXDEV`; temp должен быть рядом с целью.
- `shutil.copy`/бэкап — лишние файлы и сложность.

## R4. Когда валидировать путь

**Decision**: `resolve_output_path(raw)` вызывается в CLI после `validate_all`
(цель/рубрика/флаги) и до `load_spec`/`audit`; сама запись — после `audit`.

**Rationale**: ошибки target/spec сохраняют приоритет и текущие сообщения;
плохой путь не запускает чтение папки сдачи. Валидация в `report_html`, а не в
`validate.py`, чтобы не менять контракт фичи A.

**Alternatives considered**:
- До `validate_all` — меняет приоритет ошибок и ломает существующие тесты.
- После `audit` — зря читает сдачу и считает баллы, хотя файл всё равно не
  создать.
- В `validate.py` — смешивает вход аудита и выход экспорта.

## R5. Расширение и путь

**Decision**: требовать `.html`/`.htm`; `~` раскрывать; относительный путь
разрешать от cwd; родительские папки не создавать; целевой symlink
отклонять; symlink в родителях разрешать; путь внутри `target` разрешать;
пробелы в PATH отчёта разрешать.

**Rationale**: расширение делает артефакт предсказуемым и защищает от
случайной записи HTML в `README.md`. Запрет symlink-цели не даёт перезаписать
файл вне ожидаемого места. Запрет автосоздания папок — меньше сюрпризов.

**Alternatives considered**:
- Любое расширение — проще, но `--html report.txt` создаёт HTML с обманчивым
  именем.
- Дописывать `.html` молча — пользователь не знает итоговое имя.
- Создавать родительские папки — удобно, но маскирует опечатку в пути.

## R6. Детерминизм

**Decision**: не включать дату/время, случайные id и `hash()`; порядок находок —
порядок рубрики; сортировка на клиенте устойчивая; `render_html` — чистая
функция.

**Rationale**: одинаковый вход → одинаковые байты; отчёт можно сравнивать в
git и тестах. Конституция IV.

**Alternatives considered**:
- `generated_at` в шапке — полезно человеку, но ломает байтовое сравнение и
  требует флага/инъекции времени; вне объёма.
- Случайный id для секций — не нужен, DOM и так уникален.

## R7. `--max-findings`

**Decision**: HTML и JSON содержат все находки; `--max-findings` ограничивает
только текстовый stdout (как JSON уже сейчас).

**Rationale**: HTML должен совпадать с JSON, иначе сверка и поиск врут.
Менять существующую семантику JSON нельзя.

**Alternatives considered**:
- Резать HTML по `--max-findings` — появляется скрытая часть отчёта и
  `hidden_findings`; UI-команда справедливо возражала.
- Менять JSON — ломает публичный формат.

## R8. Клиентские фильтры

**Decision**: рендерить все находки в DOM; поиск/severity/«только провалы»/
сортировка/сброс — vanilla JS по `data-*`; без JS список остаётся полным.

**Rationale**: отчёт офлайн и без сервера; 200 элементов легко фильтруются в
браузере. Progressive enhancement сохраняет читаемость без JS.

**Alternatives considered**:
- Серверный рендер с query-параметрами — нужен сервер/перезапуск, ломает
  «один файл».
- JS-фреймворк — зависимость и сборка, запрещены конституцией IV.

## R9. Безопасность

**Decision**: `html.escape(s, quote=True)` для всех динамических строк; в
атрибутах — только контролируемые значения (`data-severity`, `data-ok`,
`data-weight`, `data-search`); CSP `default-src 'none'` + inline style/script;
никаких внешних URL.

**Rationale**: папка сдачи недоверенная; rule id/title/detail могут содержать
`<script>` и кавычки. CSP — страховка на будущее.

**Alternatives considered**:
- Экранировать только text nodes — атрибуты остаются вектором.
- Доверять рубрике — рубрика тоже пользовательский файл.

## R10. Коды возврата

**Decision**: сохранить текущие: 0/1/2 — аудит, 3 — недоступная рецензия
(в том числе при блокере), 2 — отказ пути/ошибка записи и приоритетнее 3.

**Rationale**: фича аддитивна; существующий контракт и тесты не переписываются.
UI-команда предлагала «3 только при 0/1», но это изменение поведения вне
объёма.

**Alternatives considered**:
- 2 при блокере даже с недоступной рецензией — логично, но ломает текущий
  `cli.py` и контракт `3`.
- Отдельный код 4 для ошибки экспорта — расширяет публичный контракт без
  необходимости.

## R11. Рецензия

**Decision**: передавать `narrative`/`narrative_error` без обрезки; в HTML
показывать три состояния: не запрашивалась, получена, недоступна.

**Rationale**: HTML = JSON; тихая обрезка ответа endpoint вводит в заблуждение.
Три состояния не дают спутать «не просили» и «сломалось».

**Alternatives considered**:
- Обрезка до 20 000 символов — защита от гигантского ответа, но расхождение с
  JSON; можно добавить позже отдельным решением.
- Не выводить блок без `--narrative` — пользователь не понимает, почему блока
  нет.

## R12. Границы фичи

**Decision**: не менять `core.py`, `validate.py`, `spec.py`, `narrative.py`;
не добавлять сервер, автооткрытие браузера, темы, Markdown-рендер, графики,
историю, локализацию.

**Rationale**: одна небольшая фича; границы зафиксированы в спеке и контракте.
