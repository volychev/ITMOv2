# Как писать правила рубрики

Рубрика лежит в `rubrics/practice_04.yaml`. Одно правило — одна проверяемая
мысль. Если предложение требует двух проверок, это два правила.

## Каркас

```yaml
rules:
  - id: agents_md_present      # ^[a-z][a-z0-9_]{2,63}$, уникально
    kind: file_exists          # file_exists | file_missing | file_contains | dir_count
    path: AGENTS.md            # обязателен для *_exists, *_missing, *_contains
    severity: blocker          # blocker | major | minor, по умолчанию major
    title: Правила агента на месте   # текст для человека
    weight: 2                  # 1..10, по умолчанию 1
```

Для `file_contains` дополнительно нужен `pattern` — regex. Он должен
компилироваться, иначе рубрика не пройдёт валидацию.

Для `dir_count` нужны `glob` и `min_count` (по умолчанию 1):

```yaml
  - id: evidence_transcripts
    kind: dir_count
    glob: evidence/*.md
    min_count: 3
```

## Как выбирать severity и вес

| severity | Смысл | Пример |
|---|---|---|
| `blocker` | без этого работу не примут | нет `AGENTS.md`, нет рефлексии |
| `major` | потеря баллов, но работа принимается | нет подтверждений применения |
| `minor` | аккуратность | нет reference-ресурсов у skill |

`weight` — вклад правила в баллы. Не ставь `weight: 10` ради одного блокера:
баллы должны оставаться соразмерными реальному вкладу.

## Правила, которые не работают

- `file_exists` на пустом файле. Правило скажет «есть» и промолчит.
  Добавляй `file_contains` с осмысленным `pattern`.
- Регулярка на файле больше 2 МБ: аудит его пропустит и вернёт провал
  с текстом «больше 2000000 байт, пропущен». Не проверяй таким правилом
  бинарники и PDF.
- Путь с `..` внутри папки сдачи: аудит считает это выходом за пределы
  папки и отклоняет вход.

## Порядок правил

Порядок в файле определяет порядок вывода. Сначала `blocker'ы`, потом `major`,
потом `minor`: так, читая отчёт сверху вниз, сразу видишь, с чего начать.

## Проверка рубрики перед коммитом

```sh
.venv/bin/python -m unittest discover -s tests -t tests -k test_shipped_rubric
```

Этот тест требует, чтобы рубрика в репозитории оставалась валидной. Упал —
значит, ты сделал опечатку в YAML, а не проблему в аудите.
