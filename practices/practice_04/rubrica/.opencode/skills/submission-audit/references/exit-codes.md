# Коды возврата rubrica

Полный контракт — в `docs/requirements.md`. Здесь только то, что нужно,
чтобы не перезапускать аудит в цикле.

## 0 — все правила пройдены

`score == max_score`, `failed == 0`. Проверяй `blockers == 0`, не только `0`:
код 0 гарантирует и то, и другое.

## 1 — провалы без блокеров

`failed > 0`, `blockers == 0`. Работа почти готова. Смотри список `findings`
с `ok: false` и правь по одному.

## 2 — блокер или отказ входа

Два разных случая с одним кодом:

- `findings` непустой и в нём есть `severity: blocker` → не хватает
  обязательного артефакта сдачи. Смотри `fix_hints[0]`, он прямо называет,
  что закрывать первым.
- `findings` пустой → аудит не начался. Причина в stderr, начинается с
  `ОТКАЗ:`. Обычно это несуществующая папка или битая рубрика.

Отличить можно по наличию `findings` в JSON-выводе.

## Поле `warnings`

Предупреждения не влияют на код возврата. Сейчас единственное —
обнаружение токенов вида `sk-…`, `ghp_…`, `AKIA…` в файлах папки сдачи.

Игнорировать его не стоит: это единственная защита от случайной утечки ключа
в PR.
