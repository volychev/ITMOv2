# Submission audit

Процедура проверки папки сдачи перед коммитом и перед отправкой. Нужна, когда
непонятно, всё ли на месте, и не хочется гадать по чек-листу из README.

## Когда применять

- перед `git commit` с работой;
- перед отправкой PR или сдачей;
- когда рубрика изменилась и нужно убедиться, что новые правила проходят;
- когда нужно быстро понять, что чинить в первую очередь.

Не применять для проверки кода. Код проверяет `sh scripts/check.sh`.

## Шаг 1. Прогони рубрику

```sh
.venv/bin/python -m rubrica.cli .. --spec rubrics/practice_04.yaml
```

Читай код возврата по таблице в `references/exit-codes.md`. Кратко:

| Код | Что означает | Что делать |
|---:|---|---|
| 0 | всё пройдено | можно сдавать |
| 1 | есть провалы без blocker'ов | закрыть провалы |
| 2 | blocker или отказ входа | сначала blocker'ы |

Для разбора конкретных полей добавь `--json`.

## Шаг 2. Закрой blocker'ы первыми

Блокер — это `severity: blocker` в рубрике. Пока есть хоть один блокер,
остальные провалы не разбирают: чинить всё сразу — верный способ
потерять время.

## Шаг 3. Проверь предупреждения

Строка `ВНИМАНИЕ: возможные секреты в N файлах` означает, что в папке сдачи
нашёлся токен. Это блокер по сути, даже если рубрика его не проверяет:
вынеси ключ в `.env`, удали из файла, повтори аудит.

## Шаг 4. Подтверди применение среды

Если правишь код проекта, а не папку сдачи, сначала прочитай `AGENTS.md`,
затем `docs/style-guide.md`, потом правь. Hook `check-after-edit` сам запустит
`scripts/check.sh` после каждой правки в `src/` или `tests/` — не зови runner
вручную, если правка в этих папках.

## Шаг 5. Покажи результат

Ревьюверу нужны факты, а не обещания. Покажи:

1. команду и её фактический вывод;
2. список файлов, которые ты добавил или изменил (`git status --short`);
3. для каждого провала — что именно не хватило.

Не пиши «всё готово», пока код возврата не равен 0.

## Ловушка

`rubrica` не проверяет содержимое текстов. Правило `file_exists` скажет «файл
есть» и про «пустой файл» промолчит. Если рубрика этого не требует, добавь
`file_contains` с осмысленным `pattern` в `rubrics/practice_04.yaml`.
