# rubrica — аудитор папки сдачи практики

CLI, который проверяет папку сдачи по рубрике из YAML и выдаёт вердикт с баллами.
Проект создан для практики 4: в нём одновременно две небольшие фичи и среда агента
(правила, skill, собственный MCP, hook после правки).

## Что это

Агент перед сдачей обычно сверяется с чек-листом глазами. Пропущенный
обязательный файл или сломанная рубрика обнаруживаются на защите. `rubrica`
превращает чек-лист в машинную проверку с кодом возврата, который понимает и
человек, и агент, и CI.

```sh
make install          # venv + зависимости
sh scripts/check.sh   # проверки кода: compileall + 74 теста
make audit            # аудит папки сдачи по рубрике
```

## Две фичи

**Фича A — валидация входа.** Аудит не начинается, пока не пройдены дешёвые
локальные проверки: путь существует, это папка, это не корень ФС, нет пробелов
в пути, объём в пределах, рубрика — валидный YAML нужной структуры. До этого
момента не выполнено ни одного чтения файла сдачи и ни одного сетевого запроса.
Рубрика проверяется целиком: все проблемы приходят одним списком, а не по одной.

**Фича B — деградация при отказе зависимости.** Отчё�� можно обогатить текстовой
рецензией от внешнего OpenAI-совместимого endpoint. Любой отказ зависимости —
нет ключа, недоступный хост, HTTP-ошибка, таймаут, не-JSON, пустой ответ —
превращается в понятное сообщение и **не меняет вердикт аудита**. Отдельный
код возврата 3 означает «аудит прошёл, рецензия недоступна».

Граница между ними проходит по `core.py`: аудит не ходит в сеть вообще,
вся работа с внешним миром живёт в `narrative.py`.

## Коды возврата

| Код | Значение |
|---:|---|
| 0 | все правила пройдены |
| 1 | провалы без блокеров |
| 2 | блокер или отказ входа/рубрики |
| 3 | аудит прошёл, рецензия недоступна (только с `--narrative`) |

Подробный контракт — в [`docs/requirements.md`](docs/requirements.md).

## Среда агента

| Подключение | Роль |
|---|---|
| [`AGENTS.md`](AGENTS.md) | контракт, runner, границы, что нельзя менять |
| [`docs/style-guide.md`](docs/style-guide.md) | 5 правил стиля с примерами из кода |
| skill `submission-audit` | процедура проверки перед сдачей, 3 reference-файла |
| MCP `rubrica` → `rubrica_audit` | аудит прямо из чата, структурированный JSON |
| hook `check-after-edit` | сам зовёт `scripts/check.sh` после правки в `src/`/`tests/` |
| [`docs/HANDOFF.md`](docs/HANDOFF.md) | состояние для новой сессии |

Подключения выбраны не по количеству, а по покрытию шагов задачи: правила
задают границы, skill — процедуру, MCP — способ узнать вердикт без ручной
команды, hook — убирает шаг «не забудь прогнать проверку».

## Структура

```
src/rubrica/       validate.py (A), spec.py, core.py, cli.py, narrative.py (B)
tests/             74 теста на публичные интерфейсы
mcp/rubrica_mcp/   собственный MCP-сервер, один tool
rubrics/           рубрика сдачи
scripts/           check.sh (runner), mcp-server.sh
.opencode/         skill и hook
docs/              requirements, style-guide, HANDOFF, RUBRIC-MAP
evidence/          подтверждения применения инструментов
```
