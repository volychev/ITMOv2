# AGENTS.md — правила проекта rubrica

Прочитай этот файл до первой правки кода. Он короче, чем кажется, потому что
всё остальное вынесено в документы, на которые здесь прямые ссылки.

## Контракт

Поведение программы описано в [`docs/requirements.md`](docs/requirements.md).
Этот файл — источник правды по ожидаемому поведению. Не переписывай его
под свой код: сначала обсуди изменение с человеком, потом меняй требования.

## Проверка результата

Единственная доверенная команда проверки:

```sh
sh scripts/check.sh
```

Она запускает `compileall` и весь набор тестов (`unittest`, 74 теста).
Агент запускает её сам после каждой правки в `src/` или `tests/`.
Если `scripts/check.sh` падает — работа не готова, независимо от того,
насколько правка выглядит правильной.

Точечный запуск одного теста:

```sh
.venv/bin/python -m unittest discover -s tests -t tests -k test_file_contains
```

## Что нельзя менять без поручения

- `docs/requirements.md` — контракт.
- `scripts/check.sh` — runner. Не ослабляй его, чтобы получить зелёный результат.
- `rubrics/practice_04.yaml` — рубрика сдачи.
- `.opencode/plugins/check-after-edit.js` — hook, который зовёт runner.

## Стиль

Короткие правила для этой фичи живут в [`docs/style-guide.md`](docs/style-guide.md).
Перед изменением кода прочитай его и следуй ему буквально.

## Границы фич

Фича A — валидация входа (`src/rubrica/validate.py`, `src/rubrica/spec.py`):
дешёвые локальные проверки до любого чтения папки сдачи и до любого обращения
к внешним сервисам. Аудит принципиально не ходит в сеть: `src/rubrica/core.py`
не содержит ни одного сетевого вызова, и это проверяется ревью.

Фича B — деградация при отказе зависимости (`src/rubrica/narrative.py`):
отказ внешнего endpoint не меняет вердикт аудита, только добавляет сообщение
и код возврата 3.

Не переписывай фичи без явного поручения.

## Среда агента, которую нужно применять

| Подключение | Что делает | Когда применять |
|---|---|---|
| Этот `AGENTS.md` | контракт, runner, границы | всегда, до правки |
| skill `submission-audit` | процедура проверки папки сдачи + reference по кодам возврата | перед сдачей и перед коммитом |
| MCP `rubrica` → `rubrica_audit` | аудит папки сдачи прямо из чата, без ручного CLI | когда нужно узнать, что ещё не сдано |
| hook `check-after-edit` | сам запускает `scripts/check.sh` после правки в `src/`, `tests/`, `mcp/` | автоматически, ничего применять не нужно |

## Секреты

Ключ API лежит только в `.env` и в переменной `VSELLM_API_KEY`.
Никогда не записывай его в код, документацию, коммит или отчёт аудита.
`rubrica` сам ищет токены в папке сдачи и предупреждает, если нашёл.
