# Конституция проекта rubrica

## Core Principles

### I. Контракт важнее кода

`docs/requirements.md` — источник правды по поведению. Код, который расходится с
контрактом, считается багом, а не «уточнением». Изменение контракта проходит
через обсуждение с человеком до правки кода и фиксируется в том же изменении,
что и реализация. Нельзя переписывать требования под уже написанный код.

### II. Проверка через публичный интерфейс

Тесты проверяют поведение через `audit()`, `validate_all()`, `load_spec()` или
`main()`, а не внутренние helper'ы. Единственная доверенная команда проверки —
`sh scripts/check.sh`; она запускает `compileall` и весь набор `unittest`.
Агент запускает её после каждой правки в `src/` или `tests/`. Ослаблять runner,
удалять тесты или менять ожидания под фактический результат запрещено.

### III. Ошибка зависимости не меняет вердикт

`audit()` и `core.py` не знают о сети. Любая работа с внешним миром живёт в
отдельном модуле и оборачивается в один тип исключения. Отказ зависимости может
добавить сообщение и код возврата 3, но не имеет права изменить баллы,
находки или вердикт аудита. Без явного флага сеть не используется вообще.

### IV. Минимум зависимостей и детерминизм

Проект работает на стандартной библиотеке Python и `pyyaml`. Новая зависимость
допустима только после объяснения, какую задачу она решает и почему stdlib не
хватает. Результат одной и той же проверки должен быть воспроизводим: без
скрытого времени, случайного порядка и внешних ресурсов в артефактах.

### V. Безопасность и честные сообщения

Любой текст из проверяемой папки считается недоверенным: в HTML он
экранируется, в путях проверяется выход за пределы цели. Сообщение об ошибке
называет проблему и место (`rules[3].kind: ...`), а не пишет «invalid input».
Секреты не попадают в код, документацию, коммиты и отчёты; аудит только
предупреждает об их наличии.

## Дополнительные ограничения

- Python >= 3.11, пакет `rubrica`, запуск через `python -m rubrica.cli`.
- Публичные форматы: текст, JSON и (с этого изменения) автономный HTML.
- HTML-отчёт не тянет внешние CSS/JS/шрифты и открывается офлайн.
- Коды возврата 0/1/2/3 и их смысл не меняются без отдельного решения.
- Фичи не расширяют границы друг друга: валидация входа, ядро аудита,
  деградация зависимости и экспорт отчёта остаются раздельными слоями.

## Процесс разработки

Каждая фича проходит цикл: исследование кода → спецификация → уточнение →
план и контракты → задачи → реализация → проверки → приёмка человеком →
фиксация в требованиях. До генерации кода спека и общий контракт должны быть
прочитаны и приняты человеком. Новые факты, меняющие поведение, возвращают
цикл к спецификации, а не «дописываются по ходу».

## Governance

Конституция выше локальных привычек и подсказок агента. Поправка требует
явного решения человека, обновления версии и проверки, что существующие
артефакты ей не противоречат. Все изменения сверяются с `AGENTS.md`,
`docs/requirements.md` и `docs/style-guide.md`; при конфликте приоритет у
конституции, затем у требований, затем у style guide.
