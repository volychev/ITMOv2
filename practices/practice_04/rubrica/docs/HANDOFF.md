Состояние на момент передачи. Читай вместе с `AGENTS.md` и `docs/requirements.md`.

## Что сделано

- **Фича A** — валидация входа. `src/rubrica/validate.py` отклоняет плохой вход
  до чтения файлов сдачи и до любого сетевого вызова. `src/rubrica/spec.py`
  валидирует саму рубрику и собирает все проблемы в один список.
- **Ядро** — `src/rubrica/core.py`: исполнение правил, баллы, код возврата,
  поиск токенов. `src/rubrica/cli.py`: CLI и JSON-вывод.
- **Среда агента** — `AGENTS.md`, skill `submission-audit` с тремя reference,
  MCP-сервер `rubrica_audit`, hook `check-after-edit`, runner `scripts/check.sh`.

## Проверки

```sh
sh scripts/check.sh      # 64 теста, compileall. Единственная доверенная точка.
make audit               # прогон рубрики по родительской папке сдачи
opencode mcp list        # rubrica connected
```

## Ограничения

- Рубрика проверяет наличие файлов, а не их смысл. `reflection.md` может быть
  пустым — аудит скажет «есть».
- Блокеров шесть, и все они про наличие артефактов. Качество объяснений
  оценивает ревьювер, не аудит.
- Символические ссылки не обходятся, файлы больше 2 МБ и не-UTF8 помечаются
  как непроверяемые, а не как «правило пройдено».
- Внешние ссылки (Context7, GitHub MCP) не подключены: для задачи хватает
  собственного MCP и чтения локальных файлов.
