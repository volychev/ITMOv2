# Контракт rubrica

Поведение, на которое можно опираться. Код, который этому не соответствует,
считается багом, а не «уточнением контракта».

## Назначение

`rubrica` проверяет папку сдачи практики по рубрике из YAML и выдаёт вердикт
баллов. Он нужен, чтобы перед сдачей не отправлять работу с пропущенным
обязательным файлом или сломанной рубрикой.

## Вход

```
rubrica <target> [--spec PATH] [--json] [--max-findings N] [--narrative] [--model ID] [--timeout SECONDS] [--html PATH]
```

- `target` — путь к папке сдачи.
- `--spec` — путь к рубрике YAML. По умолчанию `rubrics/practice_04.yaml`.
- `--json` — машинночитаемый отчёт в stdout.
- `--html` — сохранить автономный HTML-отчёт в файл `PATH`. Совместим с `--json` и `--max-findings`; stdout не меняется.
- `--narrative` — попытаться обогатить отчёт краткой текстовой рецензией через OpenAI-совместимый endpoint. Без этого флага сеть не используется вообще.
- `--model` — имя модели для endpoint (по умолчанию берётся из окружения, допускается переопределить).
- `--timeout` — таймаут обращения к endpoint в секундах.

## Валидация входа (фича A)

Аудит не начинается, пока не пройдены все проверки. Ни одного чтения файла
сдачи и ни одного сетевого запроса до этого момента не происходит.

Вход отклоняется, если:

- путь пустой, не существует или указывает не на папку;
- путь указывает на корень файловой системы;
- имя папки длиннее 120 символов;
- путь содержит пробелы (подсказка: заключи в кавычки);
- в папке больше 5000 файлов или больше 64 МБ;
- файл рубрики не найден, является каталогом или имеет расширение не `.yaml`/`.yml`;
- `--max-findings` вне диапазона 1..500.

Путь `--html` проверяется после `validate_all`, но до чтения рубрики и аудита.
Отклоняется пустой путь, существующий каталог, целевой symlink, расширение не
`.html`/`.htm` и отсутствующая или некаталоговая родительская папка.
Родительские папки не создаются; symlink в родителях допустим.

Валидация рубрики отклоняет: не-YAML, пустой файл, отсутствие `id`,
пустой `rules`, неизвестный `kind`, `id` вне `^[a-z][a-z0-9_]{2,63}$`,
дубликаты `id`, `severity` вне `blocker|major|minor`, `weight` вне 1..10,
`min_count` вне диапазона, отсутствие обязательных аргументов для `kind`,
некомпилируемый `pattern`, больше 200 правил. Все проблемы сообщаются
одним списком, а не по одной.

## Правила рубрики

| kind | Аргументы | Смысл |
|---|---|---|
| `file_exists` | `path` | файл есть |
| `file_missing` | `path` | файла нет |
| `file_contains` | `path`, `pattern` | regex встречается в файле |
| `dir_count` | `glob`, `min_count` | файлов по маске не меньше заданного |

Файлы больше 2 МБ и не-UTF8 помечаются как непроверяемые, а не как «нет совпадения»:
иначе аудит врёт. Символические ссылки не обходятся. Пути, выходящие за пределы
папки сдачи, отклоняются.

## Баллы и коды возврата

Балл = сумма весов пройденных правил, максимум = сумма весов всех правил.

| Код | Значение |
|---:|---|
| 0 | все правила пройдены |
| 1 | есть провалы, но ни одного `blocker` |
| 2 | есть `blocker`, либо вход/рубрика/путь `--html` отклонены, либо HTML-отчёт не записан |
| 3 | аудит пройден (0/1/2 остаётся прежним), но рецензия недоступна (ошибка внешнего сервиса) |

Ошибка записи HTML-отчёта возвращает 2 и приоритетнее кода 3: сначала
печатается обычный отчёт в stdout, затем сообщение об ошибке в stderr.
Код 3 сохраняется для недоступной рецензии, даже если аудит нашёл блокеры.

## HTML-отчёт (фича C)

`--html PATH` создаёт один самодостаточный файл: inline CSS и vanilla-JS,
никаких внешних ресурсов и сетевых запросов. Страница показывает вердикт,
баллы, счётчики, все находки (без обрезки `--max-findings`), предупреждения и
три состояния рецензии. В браузере доступны поиск, фильтр severity, «только
провалы», пять режимов сортировки и сброс; без JavaScript список находок
остаётся полным. Все динамические строки экранируются, CSP запрещает внешние
источники. HTML байт-детерминирован: одинаковый `Report` даёт одинаковый файл.
Запись атомарная: временный файл в той же папке, `fsync`, `os.replace`, права
`0600`. Подтверждение `HTML-отчёт: <абсолютный путь>` печатается в stderr,
чтобы stdout с `--json` оставался чистым.

## Формат JSON-отчёта

В JSON добавляются поля:

- `narrative` — строка с рецензией при успехе или `null`, если рецензия не запрошена или недоступна.
- `narrative_error` — строка с сообщением об ошибке зависимости, если рецензия запрошена и не получена; иначе `null`.

## Предупреждения

Аудит всегда дополнительно ищет в папке сдачи токены вида `sk-…`, `ghp_…`,
`AKIA…` и сообщает о них в `warnings`. Наличие предупреждения не меняет код
возврата, но попадает в отчёт и в stderr.
