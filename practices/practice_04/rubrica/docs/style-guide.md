# Style guide

Пять правил именно для этого проекта. Каждое проверяется кодом или runner'ом.

## 1. Проверяй поведение через публичный интерфейс

Тест вызывает `audit()`, `validate_all()` или `main()`, а не внутренний helper.
Пример: `tests/test_core.py` проверяет `audit(spec, root).exit_code`,
а не то, что внутри `_check_file_exists` сравнивается `is_file()`.

Причина: придумывая тест, агент обычно проверяет свою же реализацию, а не
заявленное поведение. Тест на публичном интерфейсе ломается, когда поведение
меняется, и молчит, когда поведение совпадает.

## 2. Ошибка зависимости не имеет права менять результат

Любая ошибка внешнего сервиса оборачивается в один тип исключения и
передаётся вызывающему. `audit()` про зависимость вообще не знает и
не должен знать: вердикт аудита не зависит от того, ответил внешний сервис
или нет.

Пример в коде: `src/rubrica/core.py::audit` не делает ни одного сетевого
вызова — вся работа с внешним миром живёт в отдельном модуле.

## 3. Не добавляй зависимость ради маленькой правки

Весь проект работает на `pyyaml` и стандартной библиотеке. HTTP-запрос к
зависимости сделан на `urllib`, а не на `httpx`. Тесты — на `unittest`,
а не на `pytest`. Перед добавлением пакета объясни в чате, зачем он нужен.

## 4. Не ослабляй runner ради зелёного результата

`scripts/check.sh` — единственная точка проверки. Запрещено: удалять тесты,
добавлять `skipUnless`, менять ожидаемые значения на фактические, комментировать
проверку. Если проверка не проходит, чинится код, а не проверка.

Пример в коде: `tests/test_spec.py::test_shipped_rubric_is_valid` требует,
чтобы рубрика в репозитории оставалась валидной после любых правок.

## 5. Сообщение об ошибке называет проблему и место

Тексты ошибок — для агента и для человека, который читает отчёт. Указывай
поле и ожидаемое значение: `rules[3].kind: допустимые значения ('file_exists', …),
получено 'teleport'`. Не пиши `invalid input` или `ошибка валидации`.

Пример в коде: `src/rubrica/spec.py::_parse_rule` собирает все проблемы
рубрики в список и показывает их одним сообщением, чтобы агент не перезапускал
аудит в цикле, узнавая по одной проблеме за раз.
