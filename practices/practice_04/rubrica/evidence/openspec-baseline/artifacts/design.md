# Design

## Context

См. `proposal.md`. Текущий CLI (`src/rubrica/cli.py`) печатает отчёт и уже умеет
деградировать рецензию. `Report` из `core.py` неизменяем после аудита. Новый
слой не должен трогать `core.py`, `validate.py`, `spec.py` и `narrative.py`.

## Goals / Non-Goals

**Goals**

- Один файл без внешних ресурсов, детерминированный и безопасный.
- Ранняя проверка пути до чтения рубрики и аудита.
- Атомарная запись, которая не портит прежний файл.

**Non-Goals**

- Не менять схему JSON и коды без `--html`.
- Не добавлять зависимости, сервер, шаблонизатор и сборку.
- Не создавать родительские папки и не следовать symlink-цели.

## Decisions

- **Отдельный модуль `report_html.py`.** Рендер не знает о CLI и сети; CLI
  передаёт готовый `Report`. Альтернатива — писать HTML в `cli.py` — смешала бы
  разбор аргументов, аудит и разметку.
- **Неизменяемая view model.** `ReportView`/`FindingView` копируют поля
  `Report`. Это отделяет HTML от внутренних классов ядра и делает рендер чистой
  функцией.
- **Строковая сборка с экранированием.** Шаблонизатор не нужен: разметка
  фиксирована, все данные проходят через `html.escape`. Альтернатива — Jinja2 —
  новая зависимость ради одного файла.
- **Inline CSS/JS и CSP.** Внешние ресурсы запрещены требованием автономности;
  CSP дополнительно запрещает сеть и внешние источники.
- **Атомарная запись через `mkstemp` → `fsync` → `os.replace`.** Прежний отчёт
  остаётся целым при ошибке; временный файл удаляется.
- **Проверка пути после `validate_all`.** Дешёвый отказ не должен зависеть от
  чтения папки сдачи; при этом `--html` не может отменить уже принятый вход.
- **stdout печатается до экспорта.** Ошибка записи добавляет код 2, но не
  скрывает результат аудита; это же делает приоритет 2 над 3 очевидным.

## Risks / Trade-offs

- [Большой HTML на 200 правил] → inline CSS/JS фиксированного размера, данные
  линейны по числу находок; лимит правил уже 200.
- [XSS через текст рубрики] → все динамические строки экранируются, CSP
  запрещает внешние источники; есть тест с `<script>` и `"><img onerror=...>`.
- [Файловая система без POSIX-прав] → права `0600` выставляются, но на
  non-POSIX монтировании ОС может их не сохранить; это ограничение среды, не
  контракта.
- [Ошибка записи после успешного аудита] → stdout уже напечатан, stderr
  объясняет причину, код 2.

## Migration Plan

Флаг аддитивный: без `--html` поведение и коды не меняются. Откат — удалить
флаг и модуль; существующие отчёты и JSON не затрагиваются.
