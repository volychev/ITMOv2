# Практика 3: локальные модели


Команды выполняются из `lab/` в bash/zsh (Windows: WSL). Прямой чат доступен и из нативного интерфейса Ollama/LM Studio.
Для слабого ноутбука сначала берите 0.8B/2B и небольшой контекст. Работа в OpenCode требует отдельной проверки ресурсов.
Модель должна работать на устройстве студента, а не через облачный API.

В папке `lab/demo` лежит тестовый сервис для проверки об него вопросов

## Домашняя работа: локальный помощник по своему проекту

Всю работу с файлами выполняет OpenCode в режиме Build: конфигурации, вопросы, результаты и `REPORT.md`. Вы обсуждаете план, оцениваете ответы и даёте агенту замечания в чате. Ручного заполнения файлов в задании нет.

Поручите рабочему агенту подключить локальную модель к отдельным тестовым запускам OpenCode с ограничением на чтение. Обсудите пять вопросов и попросите агента заранее подготовить эталонные ответы по коду. Эталоны остаются у рабочего агента и не передаются тестируемой модели.
Обязательно включите вопрос без ответа в репозитории и вопрос с ложной предпосылкой.

## Что OpenCode должен подготовить для сдачи

- REPORT.md: железо, версии, ID модели и квантизация, длина контекста, обоснование выбора.
- Modelfile корректно настроен
- make test выполняется
- настроить opencode.json
- opencode получил ответы на 5 вопросов из QUESTIONS.md сравнил их со своими возможными ответами

## Что студент показывает ревьюверу

- скидывает PR внутри своего форка из practice_3 в main
- рассказывает как прошел сетап, как всё работает, с какими ограничениями и проблемами столкнулся
- показывает демо как выполняет рандомный промпт относительно всего локального сетапа (если прям совсем проблемы, то можете записать скринкаст)

## Обоснование выбора моделей и параметров

- Базовая модель qwen3.5:4b выбрана как компромисс между качеством и ресурсами: 4B-вариант стабильно запускается на CPU без GPU и даёт достаточную фактическую точность на коротких задачах извлечения ответов из локального контекста. Более крупные варианты (7B/14B) заметно увеличивают время отклика и требования к памяти, при этом выгода на строго фактологичных запросах небольшая. Более лёгкие (3B и ниже) чаще галлюцинируют и хуже следуют системным ограничениям.
- itmo-agent (рабочий агент) получил увеличенный контекст `num_ctx 65536`, так как его задача — работать с большими инструкциями и материалами курса. Низкая температура `temperature 0.2` снижает вариативность и делает поведение детерминированнее при повторных запусках. Квантизация не задавалась явно, чтобы использовать дефолт Ollama для стабильности и избегать регрессий качества при сравнении.
- itmo-experiment (тестируемая модель) ограничен `num_ctx 4096`, чтобы минимизировать влияние размера контекста на метрику и держать время ответа коротким в повторяемых экспериментах. Температура также `0.2` — для сопоставимости с эталонами и снижения дрожания ответа. Квантизация оставлена по умолчанию: эксперимент ориентирован на поведение под контролируемыми параметрами, без смешения эффекта качества/скорости из-за разных квантов.

## Результаты эксперимента (5 вопросов)

Методика: каждый вопрос задавался в новой сессии модели itmo-experiment через локальный REST Ollama. В контекст передавались только файлы из `demo/` и Makefile'ы. Эталоны `answers.json` и отчёт не передавались.

1. Как запустить тесты? Ответ модели: «make test; вызывает demo/Makefile -> python3 -m unittest -v». Совпадает с эталоном: `lab/Makefile` и `lab/demo/Makefile`.
2. Пустое имя подписчика? Ответ: ValueError("empty name"). Совпадает; подтверждено `demo/service.py` и `demo/test_service.py`.
3. Где реализован unsubscribe? Ответ: «Нет реализации». Совпадает.
4. Какая CI-система? Ответ: «В предоставленных материалах нет ответа». Совпадает.
5. Сохраняются ли подписки после рестарта? Ответ: «Нет, в памяти; не переживают рестарт». Совпадает; подтверждено `demo/README.md` и `demo/service.py`.

Ограничения: модель следует системному промпту; в ответе на вопрос 1 добавила пояснение без ошибок. Латентность зависит от длины контекста, `num_ctx=4096` даёт приемлемое время.

Итог: конфигурация qwen3.5:4b с `temperature=0.2` дала стабильные, воспроизводимые ответы, совпавшие по сути с эталонами на всех 5 вопросах. Для учебной задачи факт-экстракции 4B достаточно.
